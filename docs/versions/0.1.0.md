# NestGen CLI 0.1.0

Ce document décrit le paquet `nestgen-cli@0.1.0`. Il est un instantané de la documentation distribuée avec cette version.

## Installation et compatibilité

Utilisez Node.js `>=24.15.0 <27`, npm 11, pnpm 10 ou Yarn Berry 4. macOS et Linux sont pris en charge ; Windows passe par WSL2 car `init` appelle Bash. Windows PowerShell/CMD, Yarn Classic, Node `<24.15.0` et Node `>=27` ne font pas partie du contrat.

```bash
npm install --global nestgen-cli@0.1.0
nestgen --version
nestgen doctor
```

`doctor` émet des diagnostics structurés pour Node, scripts du générateur, dépendances Nest/ORM et lockfile. Il ne modifie pas le projet.

## Commandes et options

```text
nestgen init [name]
nestgen module <name> [--orm typeorm|prisma] [--application name] [--dry-run]
nestgen resource <name> --fields field:type[,field:type] [--route route] [--table table]
nestgen config init|show
nestgen doctor
```

`init --no-interactive` requiert explicitement `--project-path`, `--package-manager`, `--orm`, une valeur pour Docker, Swagger, le socle d’exploitation et Git, ainsi que `--modules`. Les options `--docker`, `--swagger`, `--operations` et `--git` activent ces éléments ; leurs variantes `--no-*` les désactivent. `--operations` ajoute des sondes `/health/live` et `/health/ready`, un `x-request-id`, des logs JSON avec masquage des secrets et les hooks d’arrêt Nest, sans service externe.

`--dry-run` calcule un plan JSON versionné sans écrire. `--json` rend le succès ou l’erreur scriptable. `--application` cible une application dans un workspace Nest pris en charge. Les chemins symboliques, les métadonnées `AppModule` dynamiques et les structures de workspace non supportées sont refusés avant mutation.

Les champs acceptés sont `string`, `number`, `integer`, `decimal(precision;scale)`, `enum(VALUE|VALUE)`, `boolean`, `date` et `uuid`. `?` rend un champ nullable, `!` le rend unique ; `--indexes a+b,c` ajoute des index. Les définitions JSON de ressource sont à la version `1` et peuvent déclarer relations, filtres, recherche, tri et pagination par curseur.

## ORM, mise à jour et migrations

TypeORM 0.3 et Prisma 6 sont les deux ORM supportés. Une ressource ne convertit pas une ressource existante vers l’autre ORM et ne supprime aucun ancien fichier. Prisma exige `npx prisma generate` après un changement de schéma ; TypeORM utilise des migrations explicites avec `synchronize: false`.

`resource <name> --update` régénère uniquement les fichiers suivis par `.nestgen/generation-manifest.json`. Les fichiers modifiés depuis leur empreinte SHA-256 provoquent un conflit et toute la transaction est annulée. Les fichiers non suivis sont préservés.

Ajoutez `--migration-name <name>` à une mise à jour pour analyser les suppressions de colonnes, changements de type, champs désormais requis, contraintes uniques et relations supprimées. NestGen affiche la commande officielle `typeorm-ts-node-commonjs migration:generate` ou `prisma migrate dev --create-only`, mais ne génère ni n’applique automatiquement la migration. Relisez le plan puis exécutez la commande dans le projet généré.

## Architecture : profils et compromis

Le profil `simple` produit une ressource REST Nest conventionnelle : contrôleur, DTOs, repository et persistance ORM sont proches les uns des autres. Il convient aux CRUD simples et réduit le nombre de fichiers.

Le profil `advanced` ajoute un modèle de domaine, des contrats d’application, un port de repository et un service d’application sans décorateur Nest. L’adaptateur ORM traduit les erreurs de persistance en erreurs applicatives ; le contrôleur les convertit ensuite en HTTP `404` ou `409`. Ce profil isole mieux la logique métier et les tests, au prix de davantage de types et de fichiers. Il ne transforme pas automatiquement le profil d’une ressource déjà générée.

Chaque route porte `@ResourceAction('create' | 'list' | 'read' | 'update' | 'delete')`. Un guard existant peut lire `ResourcePolicyMetadata` avec `Reflector`. NestGen ne choisit aucun fournisseur d’identité ni guard global. Pour une politique de propriété, ajoutez `ownerId:uuid`, chargez la ressource dans votre guard et refusez lorsque l’identité déjà authentifiée ne correspond pas à `ownerId`.

## Dépannage et limites

- Un verrou `.nestgen-transaction` signale une génération interrompue : sauvegardez le projet, examinez le manifeste et restaurez les fichiers avant de retirer le verrou.
- Une erreur de préflight indique une structure Nest ou des dépendances hors contrat ; exécutez `nestgen doctor` et corrigez le diagnostic avant de générer.
- Les migrations et la publication npm restent des opérations explicites ; le CLI ne les exécute jamais à votre place.
- Les contrôles de compatibilité couvrent Node 24/25/26, Linux/macOS, Prisma, TypeORM/PostgreSQL, Docker, lockfiles npm/pnpm/Yarn et le tarball npm. Ils ne couvrent pas Windows natif.

## Changements et migration

La version 0.1.0 est la première version publique : aucune migration depuis une version antérieure n’est nécessaire. Les changements de contrat futurs seront listés dans `CHANGELOG.md` et accompagnés d’instructions de migration dans le guide de la nouvelle version.
